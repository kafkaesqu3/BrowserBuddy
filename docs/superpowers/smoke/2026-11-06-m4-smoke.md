## Retrieval benchmark

Environment: AMD Ryzen 9 9900X3D (24 logical CPUs), Linux 7.0.14 x86_64, glibc 2.39,
Python 3.12.3. Installed versions:
sqlite-vec 0.1.9, sentence-transformers 6.2.0, Torch 2.15.0, pydantic-ai-slim 2.66.0,
FastMCP 4.1.6. Exact dependencies are in `backend/uv.lock`.

The temporary fixture contains 10,000 documents, 100,000 chunks and 768-dimensional
deterministic vectors. Three retrieval runs took **1.1462, 1.1109 and 1.1579 seconds**;
all pass the two-second retrieval gate. Peak process RSS was **286,456 KiB** (about 280 MiB)
on Linux. This includes fixture construction, not a loaded embedding model. Results depend
on hardware/cache state. Model loading and query inference are excluded.

## Review and corrections

One independent whole-branch review reported no Critical findings and seven Important
findings. All seven were addressed in the correction pass:

1. Empty initial page results no longer prevent history lookup or reformulated searches.
2. Citation spans are limited to evidence actually exposed to the model.
3. Final digest budgeting counts serialized evidence, including metadata overhead.
4. Pending replacement digests retain previous readable output.
5. Automatic-digest authorization is checked before each model call, including repair.
6. Obsolete digest configurations are rejected; queued embedding work checks its generation
   inside the inference executor. Query embeddings are also bound to their generation.
7. Explicit time/session scopes prevent access to unfiltered global metadata.

Regression tests demonstrated the failures before their fixes. For the scoped metadata
guard, a controlled mutation removed the guard and all three scope cases failed; restoring
it passed. Additional tests cover blocked inference, publication failure, 100-page runner
continuation, missing native extensions, and terminal provider authorization failures.

## Remaining acceptance work

- **Real embedding model:** explicit setup reached the model host but this environment
  rejected `huggingface.co:443` with an approval-required network response. No workaround
  was attempted. Run `buddy index prepare` where downloads are permitted, then verify three
  known pages, semantic retrieval, token capacity, generation identity, and cached-only
  restart. Deterministic vectors do not validate the real tokenizer/model combination.
- **Native Windows:** the portable owner lock includes an msvcrt path, but this run used
  Linux. Validate lock exclusion/release, model setup, sqlite-vec loading and stdio there.
- **Live model endpoint (optional):** no paid or live provider calls were made. Verify
  tool calling, structured output, answer citations and digest generation with the intended
  configured endpoint. OpenAI-compatible transport alone does not establish support.
- Integration of the branch has not been performed. The worktree is preserved.

## Implementation decisions

These decisions supplement the approved design and preserve the execution ledger:

1. Treat user continuation as design approval and execute inline with independent final
   review; a scope misunderstanding would require revising the isolated branch.
2. Use a managed `feat/m4-recall` worktree and copy only the approved planning documents;
   integration remains a separate step and original working-tree edits are preserved.
3. Add capability settings with job discovery (Task 3) rather than the later CLI task because
   discovery needs them; defaults remain disabled, with no extra outbound work.
4. Preserve eager storage initialization for existing callers, guard migrations with
   temporary OS ownership, then hold ownership throughout serving; this adds a startup lock
   acquisition but avoids concurrent migration and retains API compatibility.
5. Use ordinary PyPI semantic wheels after the CPU-only registry could not resolve Torch;
   inference explicitly uses CPU, but installation/storage cost is substantially larger.
6. Widen the uv-build upper bound to include the verified stable release and the installed
   uv tool's supported build version; lockfile validation passes, but future build upgrades
   still require checking compatibility.
7. Use claim-specific digest filenames and an atomic DB pointer rather than overwriting a
   shared artifact path; this prevents stale publishers clobbering replacements, at the cost
   of retained old/orphan files until GC is designed.
8. Retain real-model and native-Windows checks as open acceptance gaps; neither synthetic
   vectors nor Linux lock tests establish those environments. The milestone stays open.
9. Treat the measured synthetic benchmark as retrieval-only evidence and leave live provider
   compatibility optional; total response latency and provider behavior remain unmeasured.

No Minor findings were deferred by the independent review.
